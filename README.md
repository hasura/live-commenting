# Live commenting

A commenting layer for generated JavaScript apps. Comments attach to stable
identities in the app's content: an element, a text range, an image region, or
selected chart data. A review server keeps the shared history and original
selection images in SQLite. The owning PromptQL bot can read and act on comments.

## How the pieces fit

- The artifact declares `data-anno-*` attributes and, for data-aware charts, a
  small geometry adapter. It does not import the annotation runtime.
- The browser library renders the commenting UI. The app host supplies identity,
  the annotation document, and a save callback.
- The [reference host](fixture/src/App.tsx) loads and saves through the
  [review server](fixture/server.mjs). The server owns persistence and PromptQL
  calls; the [bot CLI](fixture/scripts/anno.mjs) uses its local Unix socket.

The library supports React hosts and can be mounted as a React island beside a
non-React SPA. See the [integration guide](INSTRUCTIONS.md) for the required
routes, markup, chart adapters, server configuration and AppArtifact publication.

## Build and install

Use Node 24 for the reference server and builds. The browser package requires
React 19, React DOM 19 and Floating UI React 0.27.

```sh
cd fixture
npm ci
npm run build             # the example review app -> dist/
npm run build:library     # the browser library -> lib/ and live-commenting-<version>.tgz
```

A `.tgz` is a compressed npm-installable package, generated by `npm pack`. It is
ignored by Git. It contains the compiled library, CSS, declarations, independent
annotation/chart helpers, integration guide and dependency notices. It excludes
the fixture app, review server, bot CLI, databases and test output.

Use the repository directly when it is the app template. Use the package when
adding commenting to a separate app; `npm install /path/to/live-commenting-<version>.tgz`
installs it without an npm-registry release. The server and CLI come from the
matching repository checkout. A separate source archive is optional: cloning the
repository provides the same source files.

Public entry points: `live-commenting`, `live-commenting/anno`,
`live-commenting/chart`, `live-commenting/chart-adapters`,
`live-commenting/events`, `live-commenting/review`, and
`live-commenting/annotations.css`.

## What reviewers get

- Comments, replies, resolve/reopen, mentions and current-viewer presence.
- A point comment follows that point's stable identity. A rectangle keeps its
  original member set and image; new points do not join it after a data update.
- Point selections outline the mark. Rectangle selections show an enclosure and
  marker; discussion details show the image and expandable saved data.
- Missing selections move to Unanchored and return when their identities reappear.
  Open replies survive these transitions. Scrolling and collapsed sections hide
  markers without rewriting the saved selection.
- HTML/SVG titles, legends, labels and controls can be ordinary targets. Axes and
  Canvas-only labels are outside the component-targeting scope.
- Mentioning the bot, or choosing “Post directly to …”, requests its work. Human
  mentions notify those people; plain comments and bot replies send no chat receipt.
- A send failure preserves the saved comment and records the error. There is no
  automatic message retry. The waiting indicator clears on the bot's contribution.

Native chart interaction remains available outside Comment mode. Compact screens
use bottom sheets; keyboard and dismissal behavior follow the device. Detailed
interaction implementation and checks belong in [AGENT.md](AGENT.md), not in the
artifact integration guide.

## PromptQL integration

The production boundary is implemented directly in [server.mjs](fixture/server.mjs):
viewer identity, participant lookup, authorization checks and comment receipts.
There is no separate production SDK adapter. The PromptQL gateway supplies a
visitor token on each request; the server uses it for that viewer's Platform API
calls. The publishing agent's `PROMPTQL_USER_JWT` is only for AppArtifact registration,
not a shared browser identity. See [credentials and configuration](INSTRUCTIONS.md#promptql-credentials).

The [development harness](fixture/scripts/dev-server.mjs) is the local shim: it
injects a development identity, supplies a fake Platform API and starts the real
server with temporary SQLite state. Run it with `npm run dev` in `fixture/`.
It must not be published as the app.

Local integration suites exercise persistence, identity, mentions, delivery
failures, bot replies and image retrieval against that simulated boundary. A
production deployment still needs its AppArtifact registration, viewer consent,
durable bot instructions and a smoke test through the real PromptQL gateway and bot.

## Operational limits

- Collaboration uses polling. Background tabs pause polling until visible again.
- The review server is a single-process SQLite host. Preserve its data directory
  through rebuilds; the browser library has no separate persistence store.
- Selection images are limited to 1200 pixels per side and 2 MB; selection metadata
  is limited to 6 MB and 50,000 members. The server rejects oversized input.
- Snapshots are historical and immutable. Updating the library does not reconstruct
  an image that an earlier build captured incorrectly.
- The bot reads complete history through its owner-only socket. Dense selections
  can produce large JSON output; the bot can inspect it from a local file.
- WebGL depends on browser/device support and is opt-in in the fixture. Automated
  mobile checks use Chromium emulation; they are not physical-device coverage.
