The first responsive commenting slice is ready to review.

Working candidate, not a release. Select Candidate in the lab to try it. The frozen 0.2.0 baseline is still available. Comments are browser-local and sending is simulated; no messages reach a bot.

Implemented

  • Blue full-width header: comments, commenting mode, and host-reported send state. The ordinary control row measures 45px, including its border. Resolved/unanchored options move into the overflow menu.
  • Compact footer: new comments and existing discussions use the bottom surface at ≤700px width or ≤480px height. Desktop retains an anchored popover. Expand, minimize, reply and scroll within the footer.
  • Draft safety: outside tap, Escape and mode changes minimize rather than erase. Resume restores text; Cancel explicitly discards. An unposted editor blocks sending, including when minimized.
  • Reserved layout space: typed top/bottom insets let the host offset sticky headers and keep final content reachable. Visual-viewport events and safe-area padding are handled by the review shell.
  • Host integration: typed send states; reference host and skill instructions updated. No annotation-document schema or backend changes.

Deliberately not included

  • Physical iOS Safari / Android Chrome checks. Simulated visual-viewport shrink verifies geometry, not an actual OS keyboard, selection handles or browser chrome.
  • Touch text-selection and image-region gesture redesign; the baseline scrolling conflict in region mode remains.
  • Deck navigation/anchor-manifest support; off-slide unmounted targets still appear unanchored until the slide returns.
  • Unposted textarea persistence across page reload or a host unmount. Minimize/resize retention is in-memory.
  • Live shared delivery/authorization testing. The lab never calls the production send API.

Integration and rollout

The library owns the responsive review UI and exposes onLayoutChange, review and onDraftStateChange. The host reserves the insets, offsets its own sticky chrome and owns delivery truth, persistence and authorization. The skill documents tested spec/mockup/deck patterns.

Existing artifacts need a rebuild and the host inset integration; updating the repository does not change already-generated artifacts. No merge, release or package publication has been performed.
